1. EXECUTIVE SUMMARY & SYSTEM OVERVIEW
--------------------------------------------------------------------------------
The Carpooling System and Ride Allocation application is an enterprise-grade,
web-based shared mobility software platform. Designed to connect verified drivers
with passengers commuting along identical or compatible routes, the platform
optimizes vehicle occupancy, decreases transportation expenses, mitigates urban
traffic congestion, and reduces carbon emissions.

This implementation strictly realizes the complete Software Requirements
Specification (SRS v1.0) along with all supporting UML Diagrams (Use Case,
Class, Activity, Sequence, State Chart, Component, Deployment) and Data Flow
Diagrams (Level 0, Level 1, Level 2).


2. AUTHENTICATION & PORTAL ARCHITECTURE
--------------------------------------------------------------------------------
The system provides a dedicated authentication interface where incoming users
can choose between three public engagement modes:
  1. PASSENGER MODE: Search carpools, reserve vehicle seats, track trip updates,
     and print e-tickets.
  2. DRIVER MODE: Offer rides, configure intermediate stops, set fares per seat,
     and review/approve passenger booking requests.
  3. GUEST EXPLORER: Browse active platform routes without requiring an account.

ADMINISTRATIVE PRIVILEGE ELEVATION (HIDDEN ROLE SECURITY):
The Administrator role is intentionally hidden from public role listings to
maintain strict security and role isolation. An administrator can input their
dedicated credentials (e.g. admin@carpool.com / password123) into ANY login form
(Passenger or Driver mode), and the backend RBAC subsystem automatically verifies
administrator privileges, elevating the session directly to the full
Administrator Console.


3. SUPABASE DATABASE & POSTGRESQL INTEGRATION
--------------------------------------------------------------------------------
The application supports direct connectivity to Supabase Cloud PostgreSQL:
- Supabase SDK: @supabase/supabase-js with dotenv configuration
- SQL Schema File: supabase_schema.sql (Complete tables, constraints, foreign keys,
  indexes for NFR-3 performance query optimization, and seed records)
- Tables Mapped:
    * users (id, role, license, vehicle, ratings, status)
    * rides (id, driver, source, destination, stops jsonb, seats, fare, features)
    * bookings (id, ride_id, passenger_id, seat_count, fare, status, pickup/drop)
    * feedbacks (id, ride_id, from_user, to_user, rating 1-5, comments)
    * notifications (id, user_id, type, title, message, is_read)
    * complaints (id, from_user, against_user, category, status, resolution)

HOW TO CONNECT TO YOUR SUPABASE PROJECT:
1. Open your Supabase Dashboard (https://supabase.com/dashboard) and create a project.
2. Go to "SQL Editor" -> Click "New Query" -> Paste and Run `supabase_schema.sql`.
3. Go to "Project Settings" -> "API" -> Copy "Project URL" and "anon public key".
4. Open the `.env` file in the project folder and paste:
     SUPABASE_URL=https://your-project-id.supabase.co
     SUPABASE_KEY=your-supabase-anon-or-service-role-key
5. Restart the server (`node server.js`). The system will automatically connect.


4. CORE PROCESS WORKFLOWS IMPLEMENTED (DFD LEVEL 1 & 2 CORRESPONDENCE)
--------------------------------------------------------------------------------

[PROCESS P1: USER REGISTRATION, AUTHENTICATION & ACCESS CONTROL]
- Mode-Specific Registration:
  Allows registration tailored to Passenger or Driver roles. Driver registrations
  require driving license, vehicle number, and vehicle model verification.
- Universal Login Elevation:
  Processes authentication securely. Role detection directs Passengers to the
  booking console, Drivers to the fleet desk, and Administrators to the system
  governance dashboard.
- Profile Management:
  Permits profile details, contact numbers, driver vehicle data, and password
  modifications.
- Role-Based Access Control (RBAC):
  Guarantees separate access privileges across Guest Users, Passengers, Drivers,
  and System Administrators.

[PROCESS P2: RIDE SEARCH, ROUTE MATCHING & ALLOCATION]
- Multi-Parameter Ride Search:
  Allows passengers to filter rides by Departure Origin (Source), Final
  Destination, Travel Date, and Minimum Seats required.
- Intermediate Route & Waypoint Matching:
  Searches not only direct origin-destination pairs but also matches intermediate
  stops (e.g., Chennai -> Vellore on a Chennai to Bangalore route).
- Real-Time Seat Availability Validation:
  Excludes fully booked or deactivated rides from standard search results.

[PROCESS P3: RIDE BOOKING & ATOMIC SEAT ALLOCATION]
- Booking Creation:
  Authenticated passengers select seat counts, input custom pickup/drop
  landmarks, add special instructions, and calculate total fares.
- Atomic Seat Reservation:
  Deducts seats upon booking confirmation or holds them in pending status,
  preventing overbooking race conditions.
- Conflicting Booking Prevention:
  Restricts passengers from creating conflicting bookings on identical rides.
- Booking Lifecycle Management:
  Supports 5 distinct states: PENDING, CONFIRMED, CANCELLED, COMPLETED, REJECTED.
- E-Ticket & Receipt Generation:
  Generates printable and downloadable verified E-Tickets with QR/Barcode
  identifiers and ride metadata.

[PROCESS P4: DRIVER RIDE PUBLISHING & CAPACITY MANAGEMENT]
- Ride Offer Creation:
  Enables authenticated drivers to publish rides specifying Source, Destination,
  Stops/Waypoints, Date, Departure Time, Total Seats, Fare per Seat, Vehicle
  Data, and Trip Amenities (AC, Luggage, Music, Non-Smoking).
- Ride Editing & Constraint Check:
  Enforces constraints preventing drivers from decreasing total capacity below
  already confirmed passenger reservations.
- Ride Execution Lifecycle:
  Drivers can transition trips from ACTIVE -> COMPLETED (triggering feedback
  requests) or CANCELLED (notifying passengers and releasing seats).
- Passenger Request Processing:
  Drivers review incoming booking requests, accepting or rejecting them with
  optional explanatory feedback notes.
- Driver Earnings Summary:
  Aggregates total fares collected across all completed trips.

[PROCESS P5: FEEDBACK, RATING & TRUST MECHANISMS]
- Completed-Ride Gating:
  Ratings and reviews are restricted exclusively to completed rides.
- Star Rating Scale:
  Validated 1 to 5 star rating system with text review submissions.
- Live Driver Score Recalculation:
  Dynamically recalculates the driver's aggregate rating score upon review receipt.

[PROCESS P6: SYSTEM ADMINISTRATION, DISPUTES & MAINTENANCE]
- System Health & KPI Dashboard:
  Live visual metrics tracking User counts, Active Rides, Completed Bookings,
  Total Revenue Volume, and Open Grievances.
- User Moderation:
  Allows Administrators to view registered user rosters, inspect driver licenses,
  suspend/reactivate rogue accounts, or delete records.
- Ride & Booking Supervision:
  Global catalog enabling admins to deactivate rogue ride offers and resolve
  stalled booking disputes.
- Dispute & Complaint Resolution Desk:
  Passengers and drivers can file grievances; administrators assign, review,
  arbitrate, and resolve disputes with recorded audit notes.
- Database Maintenance & Recovery:
  Single-click JSON database backup downloads, restore endpoints, and sample
  data reset mechanisms.
